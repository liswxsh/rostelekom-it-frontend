# Личный кабинет Ростелеком

Фронтенд личного кабинета на React и Vite. После входа по номеру телефона и коду из СМС пользователь может посмотреть баланс, пополнить счёт, выбрать тариф, открыть профиль и проверить скорость интернета.

## Запуск

Нужны Node.js 20.19+ (или 22.12+), npm и запущенный gateway бэкенда на `http://localhost:8080`. Бэкенд запускается отдельно по инструкции в его README.

```powershell
cd C:\rostelekom\rostelekom-it-frontend
npm ci
npm run dev
```

Откройте `http://127.0.0.1:5173`. Vite слушает этот адрес и перенаправляет запросы `/api` на `http://localhost:8080`. Для прямого обращения к API можно задать `VITE_API_BASE_URL`, но на другом origin бэкенд должен разрешать CORS.

| Команда | Что делает |
|---|---|
| `npm run dev` | Запускает сервер разработки |
| `npm run build` | Создаёт сборку в `dist` |
| `npm run preview` | Показывает собранную версию |
| `npm run lint` | Проверяет код через Oxlint |

## Вход и регистрация

Начальная страница — вход по телефону. Номер вводится в формате `+7 (999) 000-00-00`; после запроса кода открывается отдельная форма для шести цифр. Если бэкенд вернул код в ответе на первый запрос, он показывается на странице для тестирования. Повторная отправка доступна после `resendAfterSeconds` секунд.

Если номер новый, после подтверждения кода открывается регистрация: фамилия и имя обязательны, отчество — нет. ФИО приводится к написанию с заглавной буквы. После регистрации или обычного входа сохраняются access- и refresh-токены. При истечении access-токена запрос повторяется после обновления токенов; сетевая ошибка обновления сама по себе не удаляет сессию. Выход очищает локальную сессию даже при недоступном сервере.

Используемые эндпоинты: `/api/auth/otp/request`, `/api/auth/otp/verify`, `/api/auth/register`, `/api/auth/refresh`, `/api/auth/logout`.

## Страницы кабинета

- **Главная:** имя пользователя, баланс и номер лицевого счёта, открытие счёта при его отсутствии, пополнение и последние операции. Данные приходят из `/api/users/me` и `/api/billing/accounts/me`; история — из `/api/billing/accounts/me/transactions`.
- **Тарифы:** предложения из `/api/services/tariffs`. На широком экране одновременно видны четыре карточки, на узком — одна; стрелки листают по одному тарифу. Описания и дополнительные возможности для известных тарифов дополняются локальными данными из `src/tariffData.js`; тарифы создаёт бэкенд.
- **Профиль:** ФИО, телефон, номер лицевого счёта и состояние текущего тарифа. Карта покрытия открывается на сайте Ростелекома в новой вкладке.
- **Тест скорости:** загрузка, отдача, ping и jitter. Страница находится в верхнем меню.

Подписки загружаются из `/api/services/subscriptions/my`. При подключении фронтенд проверяет актуальную цену и баланс, затем отправляет запрос на создание подписки. При смене тарифа сначала показывает сравнение гигабайтов, минут, СМС и возможностей, после подтверждения подключает новый тариф и отменяет прежний после успешного списания. Если подписка ожидает оплаты, её статус отображается отдельно и ожидание можно отменить. Дата следующего списания берётся из ответа бэкенда.

## Пополнение

Пополнение создаётся через `POST /api/billing/payments`. Для введённой суммы используется один `Idempotency-Key`, чтобы повторное нажатие не создало второй платёж.

- При `PAYMENT_PROVIDER=stub` фронтенд отправляет `POST` на относительный `confirmationUrl` из ответа и обновляет баланс.
- При `PAYMENT_PROVIDER=yookassa` открывается внешняя ссылка оплаты. После возврата фронтенд проверяет статус платежа через `GET /api/billing/payments/{id}` и обновляет баланс после подтверждения. Если платёж ещё обрабатывается, показывается его текущий статус; зачисление зависит от подтверждения на стороне бэкенда.

Для локального возврата из YooKassa адрес в настройках бэкенда должен совпадать с адресом открытого фронтенда, например:

```env
YOOKASSA_RETURN_URL=http://127.0.0.1:5173/payments/return
```

## Тест скорости

Измерение выполняет [LibreSpeed](https://github.com/librespeed/speedtest) через публичный сервер Sharktech в Амстердаме. Это отдельный сервис: для теста нужен доступ к `amsspeed.sharktech.net`, а результат зависит от расстояния до сервера и нагрузки на сеть. Скрипты LibreSpeed лежат в `public/`, лицензия LGPL-3.0 — в `public/librespeed/LICENSE`. Бэкенд проекта для теста скорости не используется.

## Ошибки

Фронтенд читает `detail` из ответов бэкенда в формате Problem Details и сообщения валидации из `errors` (объект или массив). Ошибки полей показываются рядом с полями, остальные — на соответствующей странице. Для сетевых сбоев и ответов без понятного текста используются короткие сообщения фронтенда.

## Структура

```text
public/
  librespeed/          # скрипт LibreSpeed и лицензия
  speedtest_worker.js  # worker измерения скорости
src/
  App.jsx              # вход и регистрация
  Dashboard.jsx        # данные кабинета, платежи, подписки и навигация
  ProfilePage.jsx      # профиль
  TariffsPage.jsx      # тарифы и сравнение при смене
  SpeedTestPage.jsx    # тест скорости
  tariffData.js        # описания и возможности известных тарифов
  api.js               # запросы, ошибки и обновление токенов
  formatters.js        # форматирование телефона, сумм и дат
  *.css                # стили страниц
vite.config.js         # Vite и proxy для API
```
